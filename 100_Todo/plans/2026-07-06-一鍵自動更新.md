# 一鍵自動更新

> 建立時間：2026-07-06 19:46
> 類型：新功能
> 狀態：待執行

## 你要做的事（一句話版）

在台股起漲雷達加入「立即更新」按鈕，透過 Cloudflare Access 保護的 Worker 安全觸發既有 GitHub Actions 更新流程，並顯示排隊、執行中、成功或失敗。

## 背景和動機

GitHub Actions 的排程不保證在 19:30 準時啟動。現有 GitHub Pages 是靜態網站，不能安全保存 GitHub Token，因此需要一個受身份驗證保護的伺服器端觸發層。

採用方案：

- GitHub Pages 保留現有公開網站與每日排程。
- Cloudflare Worker 使用 `workers.dev`，不依賴自有網域。
- Cloudflare Access 使用 Email 一次性驗證碼，只允許指定 Email。
- GitHub Fine-grained PAT 僅授權 `tw-stock-radar` 的 `Actions: write`。
- PAT 只保存為 Cloudflare Worker Secret。
- Pages 按鈕開啟受保護的更新視窗；Access 登入有效期間內，按一次即可自動觸發。

## 具體步驟

### Step 1：建立 Cloudflare Worker 專案

- 做什麼：新增獨立 Worker 目錄、Wrangler 設定、TypeScript 程式與測試設定。
- 產出：可部署到 `workers.dev` 的觸發服務。
- 注意：所有儲存庫、workflow、branch 參數固定為允許清單，不接受前端任意指定。

### Step 2：實作 Access 身份驗證

- 做什麼：驗證 `Cf-Access-Jwt-Assertion` 的簽章、issuer、audience、到期時間與 Email。
- 產出：只有 Cloudflare Access 放行且 Email 符合允許清單的請求可進入觸發流程。
- 注意：不只依賴代理層放行；Worker 本身仍執行 JWT 驗證。

### Step 3：實作 GitHub workflow dispatch

- 做什麼：Worker 使用 Secret 中的 Fine-grained PAT 呼叫 GitHub API，觸發 `update-data.yml`、`main` branch，並固定 `backfill=false`。
- 產出：按鈕可啟動既有 `Update market data` workflow。
- 注意：Token 不寫入原始碼、Pages、GitHub Actions log 或瀏覽器回應。

### Step 4：加入防重複與狀態查詢

- 做什麼：觸發前查詢最新 workflow run；若狀態為 `queued`、`in_progress`，或五分鐘內剛觸發，直接回傳既有執行狀態。
- 產出：避免連點、重新整理或多分頁造成重複更新。
- 注意：GitHub 排程與手動觸發共用同一更新流程，判斷時必須涵蓋兩種事件來源。

### Step 5：建立受保護的更新視窗

- 做什麼：Worker 提供簡潔狀態頁，登入後自動送出一次 dispatch，輪詢狀態並顯示排隊、執行中、成功或失敗。
- 產出：使用者不需進入 GitHub Actions 操作。
- 注意：失敗時顯示 Actions 執行連結；成功時提供返回雷達與重新載入資料的操作。

### Step 6：在雷達網站加入按鈕

- 做什麼：在頁首資料日期旁新增「立即更新」按鈕，以新視窗開啟 Worker URL；未設定 Worker URL 時隱藏按鈕。
- 產出：桌面與手機版均可使用的一鍵更新入口。
- 注意：Worker URL 是公開設定，不包含憑證；敏感資料仍只存在 Worker Secret。

### Step 7：部署、設定與驗證

- 做什麼：部署 Worker、啟用 `workers.dev` Access、設定唯一允許 Email、Access audience/team domain、GitHub PAT Secret，更新 Pages 的 Worker URL，執行測試並發布。
- 產出：正式網站可從按鈕完成身份驗證、觸發、查詢狀態與返回網站。
- 注意：首次設定需在 Cloudflare 與 GitHub 頁面完成外部資源建立；每個會造成外部變更的步驟在執行時需取得明確確認。

## 測試與驗收標準

- 未通過 Access 的請求不能觸發 workflow。
- 錯誤 Email、錯誤 audience、過期或偽造 JWT 均回傳 401 或 403。
- GitHub Token 不出現在前端 bundle、repository、回應內容或 log。
- 單次點擊只建立一個 `workflow_dispatch` run。
- workflow 執行中再次點擊不會建立第二個 run。
- GitHub API 錯誤、Token 過期與 workflow 失敗均有明確訊息。
- 桌面與手機可完成按鈕操作。
- 現有每日 19:30 排程、資料更新、測試與 Pages 部署維持正常。

## 預計成果

- 雷達網站新增「立即更新」按鈕。
- Cloudflare Access 保護的一鍵更新服務。
- 即時更新狀態與 GitHub Actions 失敗連結。
- 防重複觸發與最小權限 Token。
- Worker 與前端自動化測試、部署及操作文件。

## 不包含在這次的範圍

- 自動下單或券商 API。
- 公開訪客觸發更新。
- 從網站執行六個月 backfill。
- 多使用者、角色或管理後台。
- 取代原本的每日排程。

## 可能遇到的風險

- PAT 到期或被撤銷：Worker 顯示授權錯誤，文件記錄輪替流程。
- Access 設定錯誤：Worker 仍驗證 JWT 與 Email，防止繞過代理層。
- GitHub Actions 排隊延遲：狀態頁區分已成功觸發與尚未執行，不把排隊誤判為失敗。
- 瀏覽器封鎖彈出視窗：按鈕由使用者手勢直接開啟視窗，並保留可複製的更新網址。
- 重複觸發：以 GitHub 最新 run 狀態與五分鐘冷卻共同限制。
